# Video Production Playbook — Do It With AI

**Founder Hub handbook for an AI producer or editor · Updated 10 November 2026**

**Owner:** [Do It With AI](https://doitwithai.tools/) · **Language:** English

**Current status:** Use this guide for planning and any explicitly commissioned review reel. Regular production and publishing remain paused. A request for one test does not restart a batch or authorize a post.

## Start here

Open **Video Production Playbook** in the signed-in Founder Hub, or read this file directly from the repository. For another AI, give it this file and the matching **Master brief** or stage prompt at the end. Replace the bracketed inputs; share only the source assets needed for that commission. The workflow applies to any AI or editing app. A script generator or teleprompter may help with rehearsal, but measured voice takes and the shot plan control the edit.

This is a production handoff, not a transcript archive. The founder may give feedback in Hindi or Urdu; respond, script, and narrate in English. Treat a correction as a concrete change to an edit, a verification step, or a decision for the next episode. Record what was requested, what changed, what was checked, and what still needs approval.

## 1. Start with a problem the viewer recognizes

Write a specific working title that tells the viewer what they will learn: **“Your paragraph repeats the same keyword. Here’s what to change.”** A site-tour title or a list of SEO, social, and content features cannot supply a story. Define the viewer’s question, the artifact they’re working on, the one decision you’ll teach, and the visible result. Pick a fictional example when useful and label it. Keep the same paragraph, article, image, or file recognizable as its state changes.

Build the lesson in this order, allowing overlaps when they make sense:

1. **Show the friction.** Start in motion and give the viewer a visible question. Connect the first spoken line directly to what they just saw.
2. **Promise one payoff.** “I’ll show you which repeat to cut and what to put in its place” gives a reason to stay. Deliver that payoff. Add a bonus only if it gives a distinct practical check; skip generic promises to watch until the end.
3. **Explain why with a worked example.** Show the starting state, the mechanism, the action, and the resulting state. Teach the viewer how to make the decision again on their own.
4. **Bring in the tool when it helps.** An education-led reel might introduce it after teaching the method; a tool overview can bring it in earlier, at the first step the feature genuinely helps with. In both cases, establish the problem first. Show the input, the useful output, and the judgment the viewer still needs to make.
5. **Close with one useful next action.** Give the exact relevant tool, article, or prompt URL. The teaching should still work if the viewer never clicks.

When a series is explicitly commissioned, alternate education-led lessons and problem-led tool overviews. Give each episode its own visual premise, opening scenario, current research, and CTA. Full lessons usually need about 2–3 minutes; a requested review test can be about 30 seconds. Let the developed example and actual delivery decide the length. Don’t pad, rush, repeat, slow, cut off, or stretch speech to hit a number.

## 2. Direct the first five seconds as a scene

Start with a subject already in motion on the first frame. For **3–5 seconds, no narration**. Use a small, readable surprise, joke, or visual consequence specific to the concept. Sound effects can carry the action: sync a short fall, impact, snap, scrape, click, or reveal to its visible cause. No background music. Control the level of the effects and leave space for the first line to enter cleanly. Use original or properly licensed effects.

The opening must be understandable at phone size without an explanation, even if the viewer can’t yet name the lesson. Establish one focal subject, allow the consequence to register, then carry the same object or idea into the spoken hook. Avoid logos, a static title page, long setup, or a generic visual spectacle that could open any episode. A little precise text on an object is fine if it helps the viewer understand the joke.

For example, in a keyword-stuffing reel, thick blocks marked **LAPTOP REPAIR** fall from above and bury the useful words on a laptop screen. Three distinct impacts tell the joke; the last block lands and the pile settles. On the first spoken line, match cut from the pile to the repeated phrase in the same draft. For a jump-link lesson, use a different visual premise: an anchor drops past the target it was meant to catch. In each case, use the action to set up the real explanation.

## 3. Ask the owner for the right assets before locking the edit

Inventory existing material and make a shot list early. Send **one targeted request** before building a shot that depends on genuine evidence. Ask for exact pages, states, angles, source durations, and permission to use third-party material if needed. Mark what is essential and what is optional. If you can use an existing permitted asset, don’t ask the owner to duplicate it. Continue research, scripting, 3D blocking and edit planning while assets arrive; pause the dependent shot if the missing evidence is necessary. Use a labeled illustration if it can teach the same point without misrepresenting execution.

**Reusable request to the owner:**

> For [reel title], could you send these originals? **Needed:** [exact URL], one [PNG/MP4] showing [exact screen or control], then [specific action and resulting state using the same sample]. Please leave [URL, control, result or identifier] visible and hold the result still for [a few seconds]. **Optional:** [specific stock photo/context shot], [exact logo/art if not already available]. Please use a public or approved example and remove account details, private tabs, notifications, or client information before recording. An unedited, full-resolution capture is ideal; I’ll reframe and annotate it for portrait.

For moving UI, ask for one continuous recording at natural speed with clear pauses at the decision points, or a sequence of original stills if video is unavailable. Record ownership/licence and allowed usage for stock photos, footage and sound. An example shared for study is not permission to copy another creator’s footage, art, characters, claims, or voice. Inspect every intended crop for third-party faces or personal details. Use the exact supplied logo at its original aspect ratio. Brand palette: **#4A6CF7**, **#F0FDFA**, **#121723**, **#1D2430**.

Prefer supplied footage. If capturing independently, use only the owner-authorized, supported connected-browser workflow. No alternate or cloud browser, raw CDP, headless, or shell capture. Where authorized capture is unavailable, use permitted relevant footage, attributed published media, or a clearly labeled source-grounded illustration. Avoid private URLs or identifying details in the shot, script, and editable handoff.

## 4. Show the spoken action at the moment it happens

| Spoken cue for a PageSpeed Insights lesson | Picture and edit | Evidence needed |
| --- | --- | --- |
| “Open PageSpeed Insights.” | Show the actual Google tool with its name and URL entry area legible. Establish the interface briefly, then crop to the active controls. | Original screenshot or continuous recording of [PageSpeed Insights](https://pagespeed.web.dev/). |
| “Paste your article URL.” | Move focus to the URL field as the public article URL is pasted or typed. Keep enough context to identify the tool. | Same supplied session, same approved article URL. If using an animated recreation, label the interaction “Illustration” and show no invented result. |
| “Click Analyze.” | The actual **Analyze** control is large enough to read. Time the cursor movement and click to the line; keep the label clear of captions. | Same session showing the click. If using stills, animate an editorial pointer without implying the stills are live footage. |
| “Here’s where I’d look first.” | Cut to the actual completed report. Enlarge the one field, device tab, or diagnostic that drives the lesson. Hold it long enough to read. | Captured report from the same URL and device mode. Keep the report scope visible where it matters. |

**Ask for:** one clean clip covering open → paste → Analyze → completed report, or four stills covering those states. Get the report’s device mode and the URL or origin scope when those details matter. If there’s no report, demonstrate the workflow up to Analyze and explain what to look for without displaying fake scores. Never splice a report from a different URL or session into this example as though it were the result. Google distinguishes CrUX data from real users and Lighthouse lab diagnostics; missing field data doesn’t prove the page is fast. Use the metric actually observed to teach the diagnosis.

Use source time for supplied recordings. Trim and reframe; don’t stretch a desktop capture or reinterpret variable frame-rate footage as fixed-rate footage at a new speed. If a wait is long, make an honest cut to the completed state. Don’t show an invented progress clock or make a reported performance improvement out of an editorial cut. Record source intervals, crop endpoints, any hold frames, and labels in the edit list.

## 5. Build visuals that explain, in portrait

**At each beat, the current idea is the biggest and clearest thing on screen.** Keep enough context to orient the viewer. Remove completed settings, nav, sidebars, unrelated imagery, and repeated headings when the next action takes over. A comparison may need two items at once; keep both readable. Never leave a tiny full-desktop inset floating in a permanent header, media box, and footer.

- **Give 3D a job.** Use real geometry with thickness, coherent perspective, occlusion, lighting and contact shadows. Give objects a reason to move: blocks pile up and obscure content; an old PDF stays unchanged while an editor updates; an anchor locks onto the correct matching section. Use a viewpoint that makes front and side faces readable. An oblique camera angle, floating text, or stacked flat panels alone won’t show the relationship. Call layered artwork 2.5D and an animated still a still, not footage.
- **Choose the media for the thought.** Use actual UI for an observed action; 3D for a mechanism or analogy; authorized moving footage or an original context image for a real-world situation; an infographic when relationships or comparisons need explaining. Inspect generated anatomy, hands, device proportions, lighting, and relevance. Keep factual text and official artwork editable and exact. Don’t fill time with decorative stock or one photograph zooming under unrelated speech.
- **Stage the sequence as an edit.** Follow the same object through before, action and after. A motivated push-in can isolate the exact field; a pull-back can reveal a comparison; a match cut can keep the viewer oriented. Ease into a steady reading hold. Change when the action or thought changes, not at every sentence. Avoid automatic zoom pulses, looping arrows, random transitions and a white page with lines of text substituting for an explanation.
- **Compose for a phone.** Preserve source proportions. Use one short overview if needed, then reframe to the exact field, cursor, output, or selected phrase. Remove unrelated chrome. Use a short label only when it adds information. Keep captions off key controls, evidence, and the CTA. Check the actual destination UI when publishing; overlays vary by app and device. Use one coordinated caption treatment, without a permanent empty gutter.
- **Protect the brand and casting constraints.** No women in exported visuals, including stock, background art, screenshots and thumbnails; no female voice, music, or avatar presenter. A brief fictional silent male reaction is allowed when it earns its place and doesn’t imply endorsement. Use original or licensed assets. Use the supplied owner logo, unchanged, where it adds identity.

**Shot card:** record the exact spoken cue and actual time span; what the viewer needs to understand; focal subject; required context; what clears; source ID/type/time/crop and attribution; entry → action → hold → exit; caption, labels, and SFX cue; what you will check in the export. Mark the opening as **no dialogue** and give sound cues their own row. Fill measured timings after recording, never from estimated narration speed.

## 6. Worked example: keyword stuffing

This is a shot plan, not a timed recording or live test. Use roughly 30 seconds for a short review version if the speech fits naturally; a full episode can spend longer on the actual revision and tool walkthrough.

| Beat | Example speech or sound | Picture |
| --- | --- | --- |
| Cold open, 3–5 seconds | No voice. Falling-block whoosh, three timed impacts, a short settle. | Three thick **LAPTOP REPAIR** blocks fall onto the same laptop, covering the useful part of the draft. Use a readable front three-quarter angle, contact shadows and a clear final pile. |
| Hook and before | “Does your draft sound like the same search query on repeat? Let’s keep the topic and make the sentence useful.” | Match cut to the fictional draft: “Need laptop repair? Our laptop repair shop offers laptop repair.” Highlight only the repetition. |
| Action and after | “Keep ‘laptop repair’ where it tells readers what the page is about. Use the next line to answer a real question: ‘We fix cracked screens and replace worn batteries.’” | Retain **Laptop repair** as the heading. Replace the repeated line with the specific service sentence. Hold both while the viewer reads the result. |
| Check and tool bridge | “Read it aloud. If a phrase is just taking up space, cut it. The repetition checker can show you where it repeats, so you can judge each use in context.” | Show the owner’s genuine tool footage: paste the draft, select the repeated phrase, inspect a relevant occurrence. If no matching run is available, use a labeled workflow illustration, with no made-up score. |
| Soft CTA | “Try it on one paragraph.” | Show [Keyword Density & Phrase Coverage Checker](https://doitwithai.tools/tools/keyword-density-checker), the exact URL, and one relevant feature or owner asset. Hold for reading. |

Google’s spam policy describes keyword stuffing as filling a page with keywords or numbers to manipulate rankings, often unnaturally or out of context. Repetition alone doesn’t establish intent or a violation; the draft is an illustration of an editorial problem. The owner’s checker helps locate repeated phrases and review their context. It does not provide a Google score, an ideal keyword density, or a ranking prediction. The worked edit teaches the decision.

## 7. Give each reel its own CTA

Start with the question **“What would the viewer do next on this exact example?”** Search the owner’s current tools, guides, and prompts for that job. Open the exact resource. Verify what the page currently says and, when necessary and authorized, use a genuine sample or ask for a matching owner recording. For each CTA record the tool or resource name, exact URL, one relevant capability, what it needs as input, what the viewer should inspect or decide, and the genuine visual you’ll use. A feature listed on a page is not a completed test.

| Viewer’s next task | Exact resource to consider | What to show and what to leave out |
| --- | --- | --- |
| Locate repeated phrases in one draft | [Keyword Density & Phrase Coverage Checker](https://doitwithai.tools/tools/keyword-density-checker) | Paste text, select the phrase, review the occurrence in context. Leave arbitrary density targets out of the lesson. |
| Inspect page experience and performance diagnostics | [Core Web Vitals Checker](https://doitwithai.tools/tools/core-web-vitals-checker) | When relevant, show the owner tool’s URL entry and the relevant field/lab distinction with genuine evidence. Identify it as the owner tool. If the lesson also shows Google’s PageSpeed Insights, make the transition and tool identities explicit. |
| Unpack a dense paragraph | [Readability Checker and Improver](https://doitwithai.tools/tools/readability-checker) | Show a highlight or a selected passage. Compare the draft with a clearer edit that preserves meaning. Treat estimated grade as a clue; don’t set a universal target. |

The examples above were checked against the public pages for this revision, not independently executed for this document. Recheck current capabilities on every episode. When a guide or prompt is the best fit, use that exact resource. If the site has no relevant tool, don’t invent a feature or wedge an unrelated pitch into the story.

**Weak:** show the same “What Is AI SEO?” screenshot under different CTA voiceovers.

**Strong:** resolve the example, show the exact tool state or relevant owner artwork, and say, “Try it on one paragraph.” Let the exact link read on screen and put it in the accompanying post when publication is authorized. A legitimate promotional illustration must not be presented as a UI screenshot. Avoid stacked requests to click, like, follow, and subscribe.

## 8. Research and label what the viewer sees

Keep a short claim ledger with **claim, current source and retrieval date, qualification, and the visual evidence**. For technical and platform claims, start with current primary documentation. For features, use the current exact owner page and relevant first-hand evidence when available. Say what was observed. Don’t inherit claims from examples or marketing copy. Source labels should distinguish a supplied recording, a current capture, a published example, promotional artwork, original 3D, generated still, and an illustration. Keep the important provenance visible where a viewer could otherwise mistake a simulation or unrelated sample for evidence.

- **SEO and search display:** Titles and meta descriptions are author inputs. Google can choose title links from multiple sources, and snippets primarily use page content, may use a suitable description, and can vary by query. No universal character/display guarantee, ideal keyword density, ideal internal-link count, or guaranteed ranking, traffic, CTR, session time, bounce rate, or savings. Google Lens is not Googlebot. Never fabricate SERPs or analytics.
- **Page speed and images:** Diagnose what was observed. Keep lab/field data and URL/origin scope distinct. A display resize does not by itself establish smaller downloads; some sites serve a responsive variant. Fit responsive sources to the layout, compare compression quality, consider WebP/AVIF where suitable, and reserve layout space. Do not lazy-load the hero/LCP image. Write alt text according to the image’s purpose and content, use empty alt for appropriate decorative images, and avoid keyword stuffing. A logo or watermark is not an SEO requirement.
- **AI, writing and site tools:** Read actual sources before vouching for claims. A source review tool can organize checks but doesn’t certify truth or authority. Intent suggestions are heuristics, not live results. Schema must match the page, and validation doesn’t guarantee display. Recheck current Google documentation before making FAQ rich-result claims. A jump link needs a matching section ID. Downloading or extracting an image doesn’t grant reuse rights.
- **Tool capability and evidence:** Don’t invent audit values, tests, endorsements, test results, unlimited use, perfect outputs, or competitor superiority. Review generated suggestions. For extension claims, inspect the current official ZIP, version, manifest and permissions; a published simulator is not an installed test. For export workflows, keep preview, rebuild and downloaded file separate. If showing an old file, ensure it actually belongs to that example and identify a simulation as such.

Sources for the two worked examples: [Google Search spam policies: keyword stuffing](https://developers.google.com/search/docs/essentials/spam-policies#keyword-stuffing), [PageSpeed Insights interface](https://pagespeed.web.dev/), and [Google’s PageSpeed Insights documentation](https://developers.google.com/speed/docs/insights/v5/about). For creative research, [YouTube’s discussion of Shorts](https://blog.youtube/creator-and-artist-stories/youtube-shorts-deep-dive/) offers examples of fast hooks and compact stories, without establishing a universal timing formula or guaranteed performance. Teach the subject with current evidence rather than relying on this source list as a substitute for fresh research.

## 9. Direct the narration, effects and captions

Write speech for a person hearing it once. Keep complete ideas, concrete verbs and short conversational transitions: “That’s the phrase we want to keep. The next line should tell the reader what you actually fix.” Vary sentence length and direct emphasis toward a specific word or consequence. Ask for brisk, expressive performance with natural pauses. Energy should come from delivery and clear thought, not increased playback speed or clipped breaths. Pronounce the site **“Do It With AI dot tools.”** Leave production notes and non-spoken labels out of the recording script.

Use the approved male voice or a user-supplied approved take. For synthesis in the existing workflow, use **native Chatterbox Nano on PyTorch CPU**, conditioned on the bundled **synthetic male am_fenrir** reference. It isn’t a clone of a real person. Read the project’s synthesize_episode.py, generate_voice.py, download_models.py, requirements-native.txt, model manifests and voice recovery notes. The checked runtime uses Python 3.12 and official CPU torch/torchaudio 2.6. Resolve current local model/reference paths; verify hashes against the project manifests. Restore missing assets only through documented official receipts and recipes. Pinned revisions: Chatterbox **5de7a54aa4e5e2baadb0182dde554908b48b85c2**; Perth **ff1c8ac55a976971245cdd53c18d6131ca00d993**; ResembleAI/chatterbox-nano **71ccd1d0081b430592cea481f4307e764e07bc64**. Use explicit local paths and offline hub/telemetry flags at inference. Don’t import ONNX Runtime, retry its rejected telemetry, or substitute hosted speech or a different voice without authorization. If the approved runtime or reference is unavailable, disclose the exact missing item and ask for the approved bundle or take.

Reuse good takes for the same passage; redo unclear phrases or genuine script changes, retaining prior takes. Preserve pitch, pace and full intelligible words. Keep dialogue and SFX in separate stems; keep the 3–5-second opening free of dialogue and music, and duck effects when speech needs clarity. Edit obvious discontinuities without chopping or stretching speech. Review the hook and CTA for energy and pronunciation, not just transcript match.

Generate readable phrase captions from **the actual final audio** using native Whisper word timestamps. Check local alignment, names, numbers, negations, technical terms, pauses, domain pronunciation, and hallucinated tails. Use independent passes on doubtful segments. Don’t borrow timestamps from other clips or estimate them from chunk or phoneme boundaries. Keep short qualifiers with what they qualify. For a deliberate silent opening, don’t show spoken captions ahead of the voice; add a short non-speech cue only when needed to convey a meaningful sound for accessibility. Keep captions stable while the picture moves and clear of evidence.

## 10. Verify the exported reel, then hand it off

Before a full render, check one opening motion sequence and one representative action shot at phone size. Watch with sound and muted where possible. Does the opening read with no voice? Does the first spoken line pay off the opening? If the example can’t be followed from the visuals, redesign the scene before spending time on effects. If an interface is too small, recompose around the control instead of adding a label to an unreadable full desktop.

**Review the finished export:**

- Check the opening from frame one, sound-effect timing, spoken entry, before/action/after continuity, legible 3D depth, cuts, intermediate motion, camera endpoints, settled reading holds and the unique final CTA. Check both full-size and phone-size states. Watch every declared transition; sampled frames alone cannot verify continuous motion. Inspect all crops and thumbnails for incidental faces, private details and authentic branding.
- Confirm that actual UI actions line up with their exact spoken cues. Verify label and caption content, measured timing, overlaps, legibility, and clear separation from controls and URLs. Check output versus the shown input. Distinguish illustration from a run and media claims from factual evidence.
- Export **1080 × 1920, 30 fps, H.264/yuv420p, AAC, faststart**, preserving the full natural narration and the intentional SFX opening. Use one render writer, a unique candidate path, and wait for successful render exit before QA. Verify full decode, dimensions, codecs, frame count/rate/order, duration, audio completeness, peak/levels and global and phrase waveform correlation against the right final audio or mix. Keep sources immutable and spot-check out-of-order frame renders for deterministic output.
- Record what was actually inspected and what remains untested. Technical checks, ASR, and a contact sheet cannot establish perceived energy, readability in motion, or audience response. Don’t claim listening, continuous playback, audience testing, user acceptance, or publication without evidence.

**Deliver:** a named review MP4; editable project including 3D scenes, cameras, assets, fonts, and edit timeline or rendering code; final spoken script and shot cards; raw takes, full narration and SFX stems; native ASR and word/phrase timing plus SRT; source edit list, licences, claims, exact resource URL and rights/provenance; exact export settings, checks, known limits and rebuild notes. Keep original materials, older versions, and rejected tests intact. If working in an existing saved project or queue, use its current version and a guarded update; inspect destination state before retrying an ambiguous save or write. Check for active work or a saved candidate before starting; resume genuine partial work and do not duplicate a master that is only awaiting a connection.

**Review and publication are separate.** A review reel should be delivered privately for feedback. If the owner later authorizes publishing, first save the validated master and editable project, then verify each exact account and inspect for an existing matching post. Use the requested automatic workflow when supported. Keep the full master; record a concrete platform or connection exception rather than silently cutting it. Use distinct useful captions: a detailed TikTok walkthrough, a distinct practical Facebook description, and a specific YouTube title and description, each with the appropriate link and AI disclosure. Confirm the actual destination status and URL before saying it was sent or scheduled. No new automation, account changes, or historical post changes are implied by this guide.
